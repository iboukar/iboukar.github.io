Acheter un nom de domaine

Exemple de nom de domaine : agrocircular.com (~10–15 $/an). Choisissez un .com ou .io pour la crédibilité professionnelle.
2

Configurer les DNS sur Cloudflare

Si votre domaine n'est pas chez Cloudflare, ajoutez-le comme zone dans dash.cloudflare.com et modifiez les nameservers chez votre registrar.

Configuration Nameservers (chez votre registrar)
NS1 : leila.ns.cloudflare.com
NS2 : ursa.ns.cloudflare.com

(Les serveurs exacts sont fournis par Cloudflare lors de l'ajout du domaine)

Les enregistrements DNS CNAME pour le tunnel seront créés automatiquement par Cloudflare lors de la configuration du tunnel (Section C).

3

Vérifier la propagation DNS

PowerShell — Vérification DNS
nslookup app.votredomaine.com 8.8.8.8

Resolve-DnsName app.votredomaine.com
# Vérification via PowerShell natif
⚠️
La propagation DNS peut prendre de 5 min à 48h selon les TTL. Cloudflare est généralement rapide (< 5 min).
B

Cloudflare Tunnel — Installation & Configuration Windows

ℹ️
Comment ça fonctionne : cloudflared est un agent qui s'exécute sur votre machine Windows. Il ouvre une connexion chiffrée sortante vers Cloudflare. Tout trafic entrant sur votre domaine est relayé de façon sécurisée vers votre application locale. Zéro port à ouvrir sur votre routeur.
1

Télécharger & installer cloudflared sur Windows

PowerShell (en tant qu'Administrateur)
# Téléchargement via winget (Windows 10/11)
winget install --id Cloudflare.cloudflared

# OU téléchargement manuel depuis GitHub Releases
# https://github.com/cloudflare/cloudflared/releases/latest
# → Télécharger : cloudflared-windows-amd64.msi

# Vérification de l'installation
cloudflared --version
# cloudflared version 2024.x.x (built ...)
2

Authentification Cloudflare

PowerShell
cloudflared login
# → Ouvre votre navigateur sur dash.cloudflare.com
# → Connectez-vous et autorisez votre domaine
# → Un fichier cert.pem est créé dans :
#   C:\Users\VOTRE_USER\.cloudflared\cert.pem
3

Créer le tunnel

PowerShell
# Création du tunnel (nommez-le agrocircular)
cloudflared tunnel create agrocircular

# Résultat :
# Tunnel credentials written to:
# C:\Users\USER\.cloudflared\<UUID>.json
# Run this tunnel with: cloudflared tunnel run agrocircular

# Notez l'UUID affiché — il identifie votre tunnel
4

Créer le fichier de configuration du tunnel

Créez le fichier C:\Users\VOTRE_USER\.cloudflared\config.yml :

C:\Users\USER\.cloudflared\config.yml
tunnel: <VOTRE-UUID>
credentials-file: C:\Users\USER\.cloudflared\<UUID>.json

ingress:
  # Application principale AGRO-CIRCULAR OS
  - hostname: app.votredomaine.com
    service: http://localhost:80
    originRequest:
      noTLSVerify: false

  # API backend (si applicable)
  - hostname: api.votredomaine.com
    service: http://localhost:3000

  # Route de fallback obligatoire
  - service: http_status:404
💡
Remplacez localhost:80 par le port sur lequel tourne votre serveur web local (ex: localhost:8080 pour un serveur Node.js, localhost:80 pour IIS ou Apache).
5

Créer l'enregistrement DNS CNAME automatiquement

PowerShell
# Associer le sous-domaine au tunnel
cloudflared tunnel route dns agrocircular app.votredomaine.com

# Cloudflare crée automatiquement le CNAME :
# app.votredomaine.com → <UUID>.cfargotunnel.com

# Vérification dans le dashboard Cloudflare :
# DNS → Records → CNAME app → Proxied ✅
6

Démarrer le tunnel & l'enregistrer comme service Windows

PowerShell (Administrateur) — Démarrage en tant que service
# Test manuel d'abord :
cloudflared tunnel run agrocircular
# Accédez à https://app.votredomaine.com → doit afficher votre app

# Enregistrement comme service Windows (démarrage automatique)
cloudflared service install
net start cloudflared

# Vérification du service
Get-Service cloudflared
# Status : Running ✅

# Consulter les logs du tunnel
cloudflared tunnel info agrocircular
✅
Votre application est maintenant accessible depuis Internet sur https://app.votredomaine.com avec HTTPS gratuit fourni par Cloudflare. Aucun port n'est ouvert sur votre routeur.

Base de Données PostgreSQL — Installation & Sécurisation Windows

1

Installer PostgreSQL 16 sur Windows

Option A — Via winget (recommandé)
winget install PostgreSQL.PostgreSQL.16
Option B — Installeur graphique
# Télécharger depuis :
# https://www.postgresql.org/download/windows/
# → EnterpriseDB installer (.exe)
# Port par défaut : 5432
# Superuser : postgres
# Notez BIEN le mot de passe défini pendant l'installation !
2

Créer la base de données AGRO-CIRCULAR OS

PowerShell — via psql (ajoutez PostgreSQL au PATH)
# Connexion en tant que superuser
psql -U postgres

-- Création de la base
CREATE DATABASE agrocircular_os
  WITH ENCODING 'UTF8'
  LC_COLLATE 'fr_FR.UTF-8'
  LC_CTYPE   'fr_FR.UTF-8'
  TEMPLATE template0;

-- Création d'un utilisateur applicatif dédié (ne jamais utiliser postgres en prod)
CREATE ROLE agro_app WITH LOGIN PASSWORD 'MotDePasseFort@2024!' CONNECTION LIMIT 10;

-- Droits sur la base
GRANT CONNECT ON DATABASE agrocircular_os TO agro_app;
\c agrocircular_os
GRANT USAGE ON SCHEMA public TO agro_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO agro_app;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO agro_app;

-- Vérification
\du
\l
\q
3

Sécuriser l'accès — pg_hba.conf

Fichier de contrôle d'accès PostgreSQL. Chemin typique : C:\Program Files\PostgreSQL\16\data\pg_hba.conf

pg_hba.conf — Configuration recommandée (accès local uniquement)
# TYPE  DATABASE        USER            ADDRESS         METHOD

# Superuser uniquement en local (socket)
local   all             postgres                        scram-sha-256

# Application : accès local uniquement via localhost
host    agrocircular_os agro_app        127.0.0.1/32    scram-sha-256
host    agrocircular_os agro_app        ::1/128         scram-sha-256

# IMPORTANT : Ne jamais ajouter une règle 0.0.0.0/0 !
# La base de données NE DOIT PAS être exposée sur Internet directement.
postgresql.conf — bind-address (sécurité)
# Fichier : C:\Program Files\PostgreSQL\16\data\postgresql.conf

# Autoriser uniquement localhost (valeur par défaut et recommandée)
listen_addresses = 'localhost'

# Si besoin d'accès depuis le réseau local uniquement :
# listen_addresses = 'localhost,192.168.1.x'

# Redémarrer le service après modification :
net stop postgresql-x64-16
net start postgresql-x64-16
⚠️
Règle fondamentale : Ne jamais exposer le port 5432 de PostgreSQL directement sur Internet. Si votre backend applicatif est sur la même machine, une connexion localhost suffit et est sécurisée.
4

Chaîne de connexion pour l'application

Chaîne de connexion PostgreSQL (à stocker en variable d'environnement)

Ne jamais coder les mots de passe en dur dans le code source. Utilisez des variables d'environnement ou un fichier .env hors du dépôt Git (ajoutez .env au .gitignore).

Sauvegardes PostgreSQL

Script de sauvegarde quotidienne (PowerShell)
# backup_agrocircular.ps1
$date = Get-Date -Format 'yyyyMMdd_HHmm'
$backupDir = 'C:\Backups\PostgreSQL'
New-Item -ItemType Directory -Force -Path $backupDir | Out-Null

$env:PGPASSWORD = 'MotDePasseFort@2024!'
& 'C:\Program Files\PostgreSQL\16\bin\pg_dump.exe' `
  -U agro_app `
  -h localhost `
  -d agrocircular_os `
  -F custom `
  -f "$backupDir\agrocircular_$date.pgdump"

# Supprimer les sauvegardes de plus de 30 jours
Get-ChildItem "$backupDir\*.pgdump" | Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-30) } | Remove-Item

# Planifier via le Planificateur de tâches Windows :
# schtasks /create /tn "PG Backup AgROC" /tr "powershell -File C:\Scripts\backup_agrocircular.ps1" /sc daily /st 02:00 /ru SYSTEM
